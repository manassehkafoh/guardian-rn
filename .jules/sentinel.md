## 2023-10-27 - Early Returns in Constant-Time Verification Cause Length Leaks and DoS
**Vulnerability:** Constant-time comparison functions for HMAC verification in TypeScript, Kotlin, and Swift included early return checks (`if a.length !== b.length return false`). Additionally, the loops iterated over the untrusted input's length.
**Learning:** Early returns on length check defeat the purpose of constant-time comparison by leaking the expected length to timing attacks. More importantly, iterating over an untrusted string length allows an attacker to send an artificially massive string (e.g., 2GB), forcing the loop to consume excessive CPU cycles leading to a severe CPU exhaustion/Denial of Service (DoS) vulnerability.
**Prevention:** Remove early returns based on length mismatch. Incorporate length mismatch into the initial bitwise `diff` variable (`a.length ^ b.length`). ALWAYS iterate based strictly on the length of the *trusted* (locally computed) string. Pad out-of-bounds indices of the untrusted string with zero, and ensure variables used to accumulate the difference won't overflow during the comparison.
