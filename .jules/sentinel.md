## 2025-02-23 - Prevent Timing attacks in HMAC constant-time comparisons
**Vulnerability:** The constant-time comparison functions for HMAC strings in TypeScript, Kotlin, and Swift returned early if the lengths did not match, enabling a timing side-channel attack where an attacker could deduce the expected length. Note that while previous implementations returned early on length mismatch (preventing a DoS loop over a long untrusted string), removing the early return without restricting the iteration length could introduce a CPU exhaustion Denial of Service (DoS) attack if the code iterated over the untrusted input length instead of the fixed trusted HMAC length.
**Learning:** HMAC constant-time comparisons must never return early to avoid timing side-channels, and must strictly loop over the length of the *trusted* (locally computed) string. Iterating over the untrusted string's length gives the attacker control over CPU consumption. Additionally, when computing length differences in Swift or other environments with extended grapheme clusters, ensure the lengths correspond to UTF-8 byte arrays, not high-level strings.
**Prevention:** Always compare byte/UTF-8 lengths in constant time by XOR-ing them into the initial difference, and iterate using the trusted string's length, padding any out-of-bounds characters from the untrusted string with zeros.
