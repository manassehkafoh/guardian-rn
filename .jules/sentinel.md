## 2024-06-25 - Timing Side-Channel and CPU Exhaustion (DoS) in Constant-Time Equality
**Vulnerability:** The constant-time string comparison functions in TypeScript, Kotlin, and Swift returned early on length mismatch and iterated over the potentially untrusted/user-provided string length.
**Learning:** Early returns allow attackers to determine the expected string length. Iterating based on the untrusted string length allows an attacker to cause CPU exhaustion/Denial of Service (DoS) by sending extremely long strings. In Swift, truncating the bitwise accumulation difference to `UInt8` introduces signature malleability, and iterating over `.count` directly can mismatch utf8 byte lengths.
**Prevention:** Constant-time comparison must iterate strictly based on the length of the *trusted* (locally computed) string. Out-of-bounds indices of the untrusted string should be padded with zeros. Length differences should be accumulated in a wide integer type (e.g., `Int` in Swift or bitwise OR `| 0` in JS) to avoid precision loss or short-circuiting.
