## 2024-07-19 - Removed Hardcoded Passwords in Docker Compose Configurations
**Vulnerability:** Default administrative passwords (e.g., `changeme` for Elasticsearch, `admin` for Grafana) were hardcoded directly in the `docker-compose.yml` file, risking unauthorized access to sensitive analytics and dashboards if deployed out-of-the-box in an exposed environment.
**Learning:** Hardcoded credentials in infrastructure-as-code files are a significant security risk. Using environment variables requires explicit secure configuration during deployment, adhering to secure-by-default principles. Also learned that when defining inline shell commands in `docker-compose.yml` (e.g., within healthcheck blocks) that require interpolating environment variables, a double dollar sign (`$${VARIABLE}`) must be used so the variable is evaluated by the container shell instead of docker-compose early interpolation.
**Prevention:** Always extract secrets to environment variables (`${VAR}`) in `docker-compose.yml` and provide a corresponding `.env.example` file to guide operators. Never use fallback defaults like `${VAR:-changeme}`.
