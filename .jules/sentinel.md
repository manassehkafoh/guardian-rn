## 2024-06-29 - Secure Environment Variable Interpolation in Docker Compose
**Vulnerability:** Hardcoded credentials (`changeme`) in Docker Compose configurations, specifically within environment variables and inline `CMD-SHELL` scripts (e.g., `healthcheck`), exposing sensitive data in version control.
**Learning:** When passing environment variables into inline shell scripts in `docker-compose.yml`, using a single dollar sign (e.g., `${ELASTIC_PASSWORD}`) causes `docker-compose` to interpolate the value early during parsing. This can inadvertently expose the secret in the processed configuration or lead to evaluation errors.
**Prevention:** Use explicit environment variables rather than hardcoded credentials. For inline shell scripts (like `CMD-SHELL`), use a double dollar sign (e.g., `$${ELASTIC_PASSWORD}`) to escape the interpolation, ensuring the literal string is passed to and evaluated correctly by the container's shell at runtime. Always provide a `.env.example` file to document required variables without providing insecure defaults.
