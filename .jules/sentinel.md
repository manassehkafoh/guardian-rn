## 2024-09-05 - [Insecure Fallback for Cryptographic Key]
**Vulnerability:** The `generateSessionKey` function in `packages/guardian-rn/src/hooks/useGuardian.ts` fell back to generating cryptographic key material using `Math.random()` if the native module was unavailable, which is not cryptographically secure and could lead to predictable session keys if inadvertently triggered in a production environment (e.g., if the native module failed to initialize).
**Learning:** Even fallback logic for generating cryptographic material must be hardened. Relying purely on documentation to prevent `Math.random()` from being used in production is insufficient.
**Prevention:** First, try to use a secure JS-native PRNG (like `globalThis.crypto.getRandomValues`) as an intermediate fallback. If that fails and an insecure method like `Math.random()` must be used for testing, explicitly enforce dev-only usage by throwing an error if the code executes in a production environment (checking `__DEV__ === false` or `process.env.NODE_ENV === 'production'`).
