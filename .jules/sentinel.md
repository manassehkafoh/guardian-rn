## 2024-09-14 - Fix insecure cryptographic random number generation fallback
**Vulnerability:** The `generateSessionKey()` fallback function in `useGuardian.ts` used `Math.random()` to generate the 32-byte cryptographic session key when the native module was unavailable.
**Learning:** While `Math.random()` was documented as a test/CI fallback, it did not strictly enforce that it was only running in a test or development environment. If the native module failed to link or load in production, the application would silently fall back to generating weak keys. Since `Math.random()` is not a cryptographically secure pseudo-random number generator (CSPRNG), an attacker could guess the session key and spoof HMAC signatures.
**Prevention:** Harden fallbacks for cryptographic material by attempting to use `globalThis.crypto.getRandomValues` if available, and strictly enforcing dev-only usage for insecure fallbacks (like `Math.random()`) by explicitly checking `__DEV__` or `process.env.NODE_ENV` and throwing a hard error in production.
