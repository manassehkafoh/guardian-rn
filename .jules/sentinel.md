## 2025-05-28 - [CRITICAL] HMAC Timing Leak and Iteration DoS
**Vulnerability:** HMAC constant-time equal checks were vulnerable to timing side-channels via early length exit checks (`if a.length != b.length`). Furthermore, iterating over the *untrusted* user-provided string length allowed for arbitrary length iteration leading to a Denial of Service via CPU exhaustion. Iterations also caused overflow errors resulting in app crashes, and Swift iterator creation caused unneeded Array allocations.
**Learning:** Constant time checking loops must strictly iterate over the *trusted* length constraint. Iterating using untrusted constraints yields unbounded iterations. Length checking should use XOR/Bitwise operators to account for length differences, and array out of bounds needs to be padded with zeros to ensure standard iterations. Data type checking guarantees that variables like diffs do not overflow and crash the app during operations.
**Prevention:** Remove early length checks. Iterate over the statically generated *computed/trusted* strings length. Use appropriate iterators/types instead of loading values into memory via array casts. Pad missing characters over untrusted values with 0. Verify diff accumulates safely (e.g. `| 0` in TS, or `Int` accumulation in Swift).
