## 2024-05-18 - Insecure random number generator fallback
**Vulnerability:** The SDK used `Math.random()` as a fallback to generate a 32-byte cryptographic session key when the native `GuardianKeyProvider` module was unavailable. In an environment without the native module (or if it failed to initialize), the SDK would silently use weak, predictable randomness to generate the key that secures all communications, even in production.
**Learning:** `Math.random()` is acceptable as a fallback for unit tests and CI, but it must never be used to generate cryptographic material in production. Security-critical code that requires platform-provided entropy must fail hard rather than silently degrading to weak security mechanisms if the platform entropy source is absent. In addition, JavaScript environments often provide `globalThis.crypto.getRandomValues` which can be used as a more robust middle-ground fallback before throwing.
**Prevention:** Always harden PRNG fallbacks by first attempting to use `globalThis.crypto.getRandomValues`, and explicitly enforce dev-only usage (e.g., throwing an error in production if `__DEV__ === false` or `NODE_ENV === 'production'`) for weak entropy sources like `Math.random()`.
