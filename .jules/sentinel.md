## 2025-02-28 - Constant-time comparison CPU exhaustion (DoS) vulnerability
**Vulnerability:** The constant-time equality check for HMAC envelopes iterated over the length of the *first* input string, which could be the untrusted user input. It also had an early return for string length mismatch, preventing it from being truly constant-time. Iterating over the untrusted string length allows an attacker to send an extremely long string to exhaust CPU resources (DoS).
**Learning:** HMAC and other sensitive equality checks must use constant-time comparison without early returns. The loop must strictly iterate based on the length of the *trusted* (locally computed) string. Iterating over the *untrusted* (user-provided) string length introduces a severe CPU exhaustion/Denial of Service (DoS) vulnerability.
**Prevention:** Always iterate over the trusted string length in constant-time comparisons. Use bitwise XOR on the lengths of both strings to account for length differences, and pad out-of-bounds indices of the untrusted string with zero (using `| 0` for bitwise operations).
