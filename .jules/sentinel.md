## 2025-03-09 - [Constant-Time HMAC Comparison DoS]
**Vulnerability:** Constant-time string comparison functions in TS, Kotlin, and Swift (`constantTimeEqual` / `constantTimeEquals`) contained two critical flaws: 1) Using an early return on length mismatch (defeating constant-time guarantees, though acceptable in some scenarios if lengths are public), and 2) Iterating over the untrusted user-provided string's length (which allows an attacker to cause CPU exhaustion / DoS by sending massive strings).
**Learning:** Security comparisons must never blindly iterate over lengths dictated by untrusted input. In environments handling raw strings directly in memory (Node.js/JSI), a huge user-provided HMAC can cause the loop to run indefinitely or allocate excessively.
**Prevention:** Always iterate strictly over the locally computed (trusted) expected string length. Accumulate the length difference (`diff = computed.length ^ untrusted.length`) and pad out-of-bounds indices of the untrusted string with zeros or safe values during the loop.
