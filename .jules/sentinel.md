## 2025-02-13 - [CRITICAL] HMAC constant-time timing leak & DoS vulnerability
**Vulnerability:** The constant-time comparison functions for HMAC verification in TypeScript, Swift, and Kotlin were returning early on string length mismatch, causing a timing side-channel. More severely, they lacked proper iteration based on the trusted string's length, exposing the application to a Denial of Service (DoS) attack via CPU exhaustion when processing artificially long untrusted HMAC inputs.
**Learning:** Even when implementing custom constant-time checks, iterating over untrusted input length directly allows attackers to dictate loop counts, leading to CPU exhaustion vulnerabilities. Furthermore, fast-paths (like checking length first) reintroduce the timing attacks they attempt to avoid.
**Prevention:** In security checks like HMAC equality, always loop strictly over the bounds of the locally-computed, trusted string. The length disparity must be accumulated into the difference counter via a bitwise XOR, and out-of-bounds characters from the untrusted string should be padded with a neutral value (like 0). Avoid fast early returns.
