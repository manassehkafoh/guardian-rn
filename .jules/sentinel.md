## 2024-05-15 - Constant-Time HMAC String Comparison DoS and Timing Leaks
**Vulnerability:** HMAC signature validation across TypeScript, Kotlin, and Swift included early returns on length mismatch. Additionally, iterating over untrusted string lengths was possible. This exposed both a timing channel (fast fail on length) and a CPU exhaustion/DoS vector (providing astronomically large payloads forcing huge loop iterations).
**Learning:** Constant-time string equality logic must avoid early returns. Crucially, the loop must strictly iterate based on the length of the *trusted* (locally computed/expected) string, padding out-of-bounds characters from the untrusted string with zeros. Using `Int` instead of `UInt8` in Swift and bitwise OR integer coercion in TypeScript are required to handle unequal length accumulation safely.
**Prevention:** Avoid `if (a.length !== b.length) return false`. Iterate up to `trustedString.length`, masking missing indices with `0`. Include tests verifying long payloads do not freeze execution.
