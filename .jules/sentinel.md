## 2024-10-10 - Insecure Cryptographic Fallback in React Native
**Vulnerability:** The session key generation in `useGuardian.ts` fell back to `Math.random()` in environments where the native `GuardianKeyProvider` module was unavailable. `Math.random()` is not a cryptographically secure pseudo-random number generator (CSPRNG), leading to predictable session keys if this fallback was reached in production.
**Learning:** React Native environments might not always have native modules correctly linked, and standard JS fallback methods need to be robust. Relying on test/CI fallbacks like `Math.random()` natively without a strict dev-only environment check creates a high risk of cryptographic material compromise in production if the native bridge fails.
**Prevention:** Hardened the fallback to first attempt to use the standard Web Crypto API (`globalThis.crypto.getRandomValues`) if available. Crucially, strictly enforced a development-only check (`__DEV__` or `NODE_ENV !== 'production'`) before falling back to `Math.random()`, explicitly throwing an error and failing securely in production environments instead of generating insecure keys.
