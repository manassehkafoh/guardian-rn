## 2024-06-12 - Critical DoS and Timing Attack in Constant-Time HMAC String Comparison
**Vulnerability:** The constant-time HMAC comparison functions in TypeScript, Kotlin, and Swift were returning early on string length mismatches (exposing a timing vulnerability) and iteratively bound checking on the *untrusted* payload length instead of the trusted string's length (which allows attackers to pass enormous arrays to cause memory/CPU exhaustion).
**Learning:** Returning early defeats the point of a constant-time execution test. Furthermore, iterating over untrusted string lengths allows Denial of Service (DoS) due to unconstrained execution iterations. Constant time bounds checking requires padding the out-of-bounds inputs.
**Prevention:** Iteration limits must always be bounds-checked on the length of the locally computed or explicitly bound-limited inputs. Furthermore, difference accumulation checks should only ever start with lengths XORed together instead of an initial `0` to keep computations equivalent without branching.
