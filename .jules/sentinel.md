## 2024-10-16 - Prevent Weak Session Key Generation Fallback in Production
**Vulnerability:** The `generateSessionKey()` fallback in `useGuardian.ts` defaulted to `Math.random()` to generate the 32-byte cryptographic session key when the native React Native `GuardianKeyProvider` module wasn't available. `Math.random()` is not a CSPRNG and generates predictable outputs. If the SDK is deployed in production environments where the native module is misconfigured or fails to load, `Math.random()` would be silently used for cryptographic signing.
**Learning:** It existed to provide a fallback for testing and CI environments, but lacked a strict separation of concerns regarding execution environments. Security boundaries must not silently downgrade to insecure mechanisms when the preferred mechanism is unavailable.
**Prevention:** Do not use `Math.random()` for cryptographic material. If it is strictly required for CI/Test environments without native dependencies, enforce dev-only usage by explicitly throwing an error in production environments (e.g., checking `__DEV__ === false` or `NODE_ENV === 'production'`) if the native secure provider is missing. Additionally, attempt to use the stronger built-in fallback `globalThis.crypto.getRandomValues` before ever resorting to `Math.random()`.
