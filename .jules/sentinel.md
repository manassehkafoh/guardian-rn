## 2024-06-13 - Secure Constant-Time Equality
**Vulnerability:** The `constantTimeEqual` function in `HmacEnvelope.ts` used an early return on length mismatch (a timing attack vector) and iterated over the length of the untrusted string `a`. Iterating over the untrusted string length opens up a severe CPU exhaustion / DoS vulnerability if an attacker provides a maliciously long string.
**Learning:** Constant-time string comparison for security checks (e.g., HMAC verification) must not early return. More importantly, it must always iterate over the length of the *trusted* (locally computed/expected) string, padding out-of-bounds indices of the untrusted string with zeros. Using bitwise `| 0` ensures 32-bit integer coercion which prevents type-related issues in JS.
**Prevention:** When implementing constant-time checks, verify that the loop boundary is strictly based on `trusted.length` and any length mismatch check is bitwise accumulated rather than triggering an early return.
