## 2024-06-21 - [HMAC Timing Attack and DoS Vulnerabilities]
**Vulnerability:** HMAC string comparisons in `HmacEnvelope.ts`, `HmacSigner.kt`, and `HmacSigner.swift` had early returns on length mismatch (allowing timing attacks to discover expected lengths). Furthermore, if they had iterated over the untrusted string's length, it would have introduced a severe CPU exhaustion (DoS) vulnerability.
**Learning:** For constant-time equality checks involving untrusted input, returning early on a length mismatch defeats the purpose, enabling length discovery. Secondly, the iteration must strictly be bounded by the *trusted* string length; iterating over the untrusted length permits an attacker to send an arbitrarily long string, consuming CPU resources (DoS). Platform-specific nuances matter (e.g. accumulating differences into an `Int` in Swift to avoid truncating byte length mismatches).
**Prevention:** Always compare the full length of the trusted string. Accumulate the length difference initially (`trusted.length ^ untrusted.length`), loop strictly over the trusted length, and securely pad the untrusted string's character codes with 0 if out-of-bounds.
