## 2024-11-20 - [Insecure Fallback for Cryptographic Session Key]
**Vulnerability:** The SDK fell back to using `Math.random()` to generate a 32-byte cryptographic session key when the native module `GuardianKeyProvider` was unavailable. `Math.random()` is not cryptographically secure, leading to predictable session keys in environments without the native module.
**Learning:** Hardcoded fallbacks in secure code can inadvertently be triggered in production if the primary secure method fails or is unexpectedly missing. Even if originally intended only for CI or test environments, lack of explicit environment checks means these insecure paths could become active in production.
**Prevention:** When fallback methods (like `Math.random()`) are used, they must be explicitly guarded behind strict environment checks (e.g., development mode or testing flags). Furthermore, explicitly attempt standard alternatives (e.g., `globalThis.crypto.getRandomValues`) before resorting to an insecure fallback or throwing a fatal error.
