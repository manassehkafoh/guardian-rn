## 2024-10-07 - Insecure PRNG Fallback for Key Generation
**Vulnerability:** A fallback mechanism for cryptographic session key generation used `Math.random()` to generate the 32-byte key when the native `GuardianKeyProvider` module was unavailable. While documented as a test/Storybook fallback, there were no runtime guards preventing this insecure fallback from executing in production if the native module failed to load.
**Learning:** Documenting that an insecure mechanism is "only for testing" is insufficient security. If a fallback path exists, it will eventually be hit in production due to linking errors or environment changes. Cryptographic key material generation must hard-fail rather than silently falling back to low-entropy sources.
**Prevention:** Always enforce explicit runtime environment checks (e.g., `__DEV__` or `NODE_ENV`) before allowing insecure fallbacks. Additionally, when needing non-native randomness in modern JS environments, attempt to use `globalThis.crypto.getRandomValues()` before resorting to `Math.random()`.
