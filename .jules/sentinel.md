## 2024-10-03 - [Insecure Cryptographic Fallback in Session Key Generation]
**Vulnerability:** The session key generation mechanism in `packages/guardian-rn/src/hooks/useGuardian.ts` incorrectly fell back to `Math.random()` to generate a cryptographic key (used for HMAC signatures) when the native module was unavailable, even in production environments.
**Learning:** Hardening cryptographic material generation is essential. It's critical not to silently default to insecure pseudorandom number generators like `Math.random()` for critical session material (e.g., HMAC keys). If the native CSPRNG (e.g., via a TurboModule) fails, secondary robust fallbacks like `globalThis.crypto.getRandomValues` should be attempted. Most importantly, if secure randomness cannot be obtained, the application must explicitly fail loudly in production instead of compromising security under the guise of availability or fallback behavior.
**Prevention:** Implement strict bounds checking on test-only fallback mechanisms (using `__DEV__` or `NODE_ENV`). Throw fatal errors in production if required cryptographic capabilities (e.g., `NativeModules.GuardianKeyProvider`) are missing, and always try secondary secure methods (`crypto.getRandomValues`) before falling back.
